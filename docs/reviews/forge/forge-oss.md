# forge-oss — useful generation ideas, unfinished application routing

## Decision

**Adapt selected template-generation mechanisms; use the IDE routing design as historical reference, not the new runtime. Exclude its UI scaffolding from the initial framework.** This repository combines a real YAML/Mustache pipeline with generated command/router structures, shell-based developer tooling, and starter UI modules. Treating all of it as a ready-made application framework would import incomplete behavior and blur build-time tooling with runtime concerns.

**Snapshot:** public repository, default branch `main`, commit `5cf9173aabc213082b2fa1b60e189feb05daab36`, inspected 2026-10-30. Branch inventory returned only `main`. No repository-specific `AGENTS.md`, local skill, README, or GitHub Actions workflow was present in the complete pinned tree. Sources below link to the exact reviewed revision.

## A working source-level flow: generation

The render API reads YAML, normalizes its top-level header/payload shape, builds a context, reads and compiles a Mustache template, renders the result, and returns text. The context builder combines header and payload fields, adds naming variants and structural flags, then exposes a normalized header plus expanded payload to templates. It is a real pipeline with filesystem error propagation, not merely a plan. [Rendering entry point](https://github.com/roachmaster/forge-oss/blob/5cf9173aabc213082b2fa1b60e189feb05daab36/crates/forge-template/src/codegen/mod.rs#L16-L35), [context builder](https://github.com/roachmaster/forge-oss/blob/5cf9173aabc213082b2fa1b60e189feb05daab36/crates/forge-template/src/context/codegen_ctx.rs#L16-L66), [template renderer](https://github.com/roachmaster/forge-oss/blob/5cf9173aabc213082b2fa1b60e189feb05daab36/crates/forge-template/src/codegen/render.rs#L6-L20).

The CLI can emit context previews or rendered text, write a specified output file, and inspect intermediate forms. The procedural macro resolves template/YAML paths against an environment-provided root, invokes the same rendering library, and parses its output as Rust tokens. These are build/development mechanisms. The presence of a header/payload shape in generator inputs is not evidence of the requested network ingress bridge. [CLI rendering](https://github.com/roachmaster/forge-oss/blob/5cf9173aabc213082b2fa1b60e189feb05daab36/crates/forge-template/src/cli/render_cmd.rs#L24-L98), [macro pipeline](https://github.com/roachmaster/forge-oss/blob/5cf9173aabc213082b2fa1b60e189feb05daab36/crates/forge-proc/src/templates.rs#L7-L40).

Useful general ideas include explicit input/output stages, inspectable intermediate representations, consistent identifier expansion, and one library used by multiple developer-facing entry points. They could support an optional project initializer or code-generation package. The new framework should still work with handwritten Rust; generation should reduce repetition rather than become a mandatory hidden runtime language.

## An unfinished flow: router to provider

The generated router delegates a request to a provider registry. The registry owns a map of command kinds to shared command objects, and a command trait has an async execution method. However, dispatch matches fixed request variants and calls four helper methods that all contain `todo!()`. It never retrieves a registered command and executes it. The main CLI does not construct or exercise the router; its build path launches a shell generator and its render path prints a future-work message. [Router](https://github.com/roachmaster/forge-oss/blob/5cf9173aabc213082b2fa1b60e189feb05daab36/crates/forge-ide/src/router.rs#L15-L43), [registry and unfinished dispatch](https://github.com/roachmaster/forge-oss/blob/5cf9173aabc213082b2fa1b60e189feb05daab36/crates/forge-ide/src/provider.rs#L16-L84), [CLI wiring](https://github.com/roachmaster/forge-oss/blob/5cf9173aabc213082b2fa1b60e189feb05daab36/crates/forge-ide/src/main.rs#L38-L89).

Therefore the repository demonstrates an architectural vocabulary—request, response, command, provider, router—but **not a functioning common ingress dispatcher**. Registration itself does not prove dispatch works. The request enum is coupled to IDE operations, and its variants carry no operation-specific payload. Copying it as the framework kernel would require editing a central enum and match whenever capabilities change, recreating the god-crate pressure the new design must avoid. [Request/response schema](https://github.com/roachmaster/forge-oss/blob/5cf9173aabc213082b2fa1b60e189feb05daab36/crates/forge-ide/src/schema.rs#L13-L38).

Likewise, the template `serve` command prints a startup message and returns success without binding a socket or serving requests. The UI-components package has initializer placeholders, not a rendering engine. Names and CLI help must not be reported as implemented capabilities. [Service placeholder](https://github.com/roachmaster/forge-oss/blob/5cf9173aabc213082b2fa1b60e189feb05daab36/crates/forge-template/src/cli/serve_cmd.rs#L1-L8), [UI placeholder](https://github.com/roachmaster/forge-oss/blob/5cf9173aabc213082b2fa1b60e189feb05daab36/crates/forge-web-ui-components/src/button/model.rs#L1-L7).

## Problems worth carrying forward as lessons

**An observed test/implementation mismatch should block unqualified reuse.** The integration test expects a naming expansion for a field named `mod`; the expansion whitelist contains `module` but not `mod`. Following the inspected code, that expected generated key is absent. This is a static finding indicating a likely failing assertion, **not a test failure observed by execution**. Resolve it before calling the generation path verified. [Test expectation](https://github.com/roachmaster/forge-oss/blob/5cf9173aabc213082b2fa1b60e189feb05daab36/crates/forge-template/tests/expand_tests.rs#L12-L42), [expansion policy](https://github.com/roachmaster/forge-oss/blob/5cf9173aabc213082b2fa1b60e189feb05daab36/crates/forge-template/src/codegen/expand.rs#L64-L76).

**Normalization silently discards malformed sections.** Non-object headers/payloads become empty objects, and payload fields overwrite same-named header fields in the expanded view. This may be convenient for developer templates but is inappropriate as a default network-boundary validation policy. The ingress bridge should reject malformed routing metadata and define trusted-header precedence explicitly. [Normalization](https://github.com/roachmaster/forge-oss/blob/5cf9173aabc213082b2fa1b60e189feb05daab36/crates/forge-template/src/context/condition.rs#L9-L36), [merge behavior](https://github.com/roachmaster/forge-oss/blob/5cf9173aabc213082b2fa1b60e189feb05daab36/crates/forge-template/src/context/codegen_ctx.rs#L45-L65).

**“Dry run validated” is stronger than what runs.** The dry-run branch builds and prints the context, then returns before the template is read or compiled. A missing or invalid template is not validated there. Unknown inspection targets print a diagnostic but still return success. Automation needs truthful status and failure propagation. [Dry-run branch](https://github.com/roachmaster/forge-oss/blob/5cf9173aabc213082b2fa1b60e189feb05daab36/crates/forge-template/src/cli/render_cmd.rs#L55-L77), [inspection exit behavior](https://github.com/roachmaster/forge-oss/blob/5cf9173aabc213082b2fa1b60e189feb05daab36/crates/forge-template/src/cli/inspect_cmd.rs#L60-L74).

**Generation is coupled to shell layout and ambient tools.** The IDE invokes a relative script; that script expects `forge-template` on PATH and writes directly into checked-in source files. Formatting failures and missing generation inputs can be reported without making the overall script fail. A modern initializer should use explicit pinned tool versions, staged output, deterministic diffs, and a non-mutating check mode. [Generation script](https://github.com/roachmaster/forge-oss/blob/5cf9173aabc213082b2fa1b60e189feb05daab36/scripts/gen_forge_modules.zsh#L39-L92).

**Compile-time file access is not a plugin system.** The proc macro reads local files and emits compiled Rust; there is no dynamic ABI loading. Its handwritten literal parser strips quotes instead of fully parsing Rust string escapes, and its environment-based root is required even for absolute inputs. Keep this optional developer tooling, and do not turn untrusted runtime requests into template compilation jobs. [Argument parser](https://github.com/roachmaster/forge-oss/blob/5cf9173aabc213082b2fa1b60e189feb05daab36/crates/forge-proc/src/args.rs#L7-L56), [macro path resolution](https://github.com/roachmaster/forge-oss/blob/5cf9173aabc213082b2fa1b60e189feb05daab36/crates/forge-proc/src/templates.rs#L7-L40).

## How it should influence framework assembly

Retain generation as a separate optional developer capability. Implement the runtime's common ingress bridge and typed handler registration independently, then add initializer templates that generate code using those stable APIs. REST and Kafka adapters normalize transport input into one envelope; the bridge validates headers and selects one handler; successful application results may generate internal events for fan-out. Do not reuse the IDE's fixed request enum as that universal router.

For a small first milestone, generate one handler and its contract test, make the same handler callable from both transport adapters, and verify generated output by diff without overwriting hand-edited files. That captures this repository's useful ambition while avoiding its main failure mode: a convincing collection of architectural parts that has not yet been wired into a tested end-to-end system.
