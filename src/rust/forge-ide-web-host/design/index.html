Saved chats and archived runs

A saved chat opens its transcript and this tab’s draft. The current workspace identifies chats by slot. Stable chat IDs would let the list reorder without moving drafts between conversations.

An archived run is one submitted exchange snapshot. It opens read-only. Continue as new chat starts a separate conversation, preserving the archived snapshot.

Retention and deletion

The preview uses UTC. Keep through includes the selected date. Expiration begins at midnight UTC the next day. Keeping a chat long term removes its scheduled expiration.

Delete asks you to confirm the named saved chat. Archived runs remain read-only.

Workspace data flow

  1. Browser

    Keeps a random tab identifier in session storage and requests a saved workspace.

  2. Forge web host

    Checks the active session, request origin, and CSRF token before forwarding.

  3. Agent Runner

    Validates the checkpoint, tab lease, and save revision.

  4. PostgreSQL

    Stores the operator’s Chat history and separate tab checkpoints.
