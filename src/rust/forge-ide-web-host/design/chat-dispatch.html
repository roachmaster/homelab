PostgreSQL event dispatch for Forge GPU inference

Proposed design. Mission Control accepts chat turns while Forge GPU is offline. A worker on Forge claims pending jobs from PostgreSQL and calls the model locally.

Overview Sequence diagram DAO DTOs Connection Rollout

Inference responsibilities

Deployed today

The Mission Control runner writes runs, input messages and replayable events to PostgreSQL. Its worker calls Forge GPU over the existing inference tunnel. The chat compatibility route can query the active model before queueing and wait up to 13 seconds for a reply. PostgreSQL accepts local Unix socket connections.

Proposed deployment

Mission Control commits the chat turn and returns a run ID. Forge GPU claims the job and publishes a result through PostgreSQL. Mission Control commits the transcript and serves ordered events to the browser.

PostgreSQL stays on Mission Control and is the shared availability dependency. During a database outage, the API cannot confirm new jobs and Forge cannot claim work or publish results. Committed jobs and results are available after database recovery.

Request and completion sequence

PostgreSQL data access

The queue reuses runs, messages and run_events. Each run tracks a lease deadline, attempt number, attempt token, next eligible time and absolute run deadline. The result inbox stores one result per run with a cascading foreign key.

Admit a run
Pin an allowed model and atomically store the input, run and queued event. Forge records its ready model and last-seen time so the IDE can show Waiting for Forge.
Claim and renew a lease
Claim the oldest eligible unlocked job for a supported model with FOR UPDATE SKIP LOCKED. Use the database clock for lease renewal and release the transaction before inference. A lost lease allows retry within the run limits. Only the current attempt can publish an accepted result. PostgreSQL 16 row locking
Publish a result
Check the current attempt and lease, store a bounded result, set the run to result_ready and notify Mission Control in one transaction. A retry of an accepted publication can return its existing receipt or terminal status. A run with a published result is ineligible for another claim.
Finalize a run
Drain the inbox on startup and reconnect. Apply the existing chat DAO rules and acknowledge the result in the same transaction as the terminal event and transcript update.

LISTEN/NOTIFY wakes the workers. Run and result rows provide durability. Commit LISTEN, scan in a new transaction and rescan on notification, timer or reconnect. Use empty notification payloads because notifications are visible to other database users. PostgreSQL 16 LISTEN · NOTIFY

Mission Control expires unfinished jobs at the run deadline. A result accepted before the deadline can still finalize if the chat is available. Acquire locks in chat, run, then result order. Cancellation, deletion and chat expiry invalidate later writes. Deletion and expiry purge related work and receipts. Finalization checks the current chat policy and accepted attempt. Previous chats technical design

Header routing and data transfer objects

The browser sends POST /forge/v1/dispatch with the existing session and CSRF checks. The Forge-Destination header selects the operation.

ide.chat.run.submit
Send a stable chat ID, the new turn and an idempotency key. Include the expected revision for a continuation. Receive 202 Accepted with the run ID, chat ID and queued status after commit. Retrying with the same key returns the existing run.
ide.chat.run.events
Send the run ID and after_sequence. Receive the current state, a bounded page of ordered events and the next sequence cursor. A completed run also returns the saved reply and chat revision.
ide.chat.run.cancel
Send the run ID. Receive the current cancellation or terminal status.

The IDE keeps the pending run ID in its tab checkpoint. A reload resumes authorized event reads even for a first turn that is still waiting to appear in Previous chats. The browser uses short event-page requests because the current web host serves one request at a time. Chat history actions keep their existing destinations.

Worker claim DTO

Run ID, model, bounded inference input, attempt token and deadline.

Worker result DTO

Run ID, attempt token and bounded reply or failure.

PostgreSQL derives the worker identity from its connection role. Mission Control derives chat ownership from the admitted session.

Connection and privileges

Forge initiates an SSH forward to a PostgreSQL listener bound to Mission Control loopback. Mission Control keeps its Unix socket connection. Limit the forwarding account to the database destination and disable shell and subsystem sessions. Limit host-based authentication on loopback to the agent database and the Forge worker login. OpenSSH forwarding controls · PostgreSQL host-based authentication

Give the Forge login execution grants for worker readiness, claim, renew and publish operations. It receives inference input through the claim and has no table grants for chat history, browser checkpoints or unrelated jobs. Use a trusted function search path and revoke public execution in the same transaction that creates the functions. PostgreSQL function privileges

Cutover and acceptance checks

  1. Stage dispatch

    Exercise the queue operations, role and API with a fake Forge worker and disposable PostgreSQL. Drop the notification listener during submission and verify the reconnect scan finds the job.

  2. Test offline and retry

    Submit with Forge off and verify the job completes when Forge returns. Test duplicate submission, a worker crash, a rejected late result and a Mission Control restart after publication.

  3. Test browser and retention

    Reload during the first turn. Test cancellation, chat deletion and expiry during inference. Track queue age, worker heartbeat, lease expirations and time in result_ready.

  4. Move inference to Forge

    Drain and disable the legacy worker before enabling Forge claims. Its recovery process marks running jobs interrupted. Retire the old inference tunnel after verification. To roll back, stop Forge claims and resolve its leases and receipts before restoring the legacy worker.
